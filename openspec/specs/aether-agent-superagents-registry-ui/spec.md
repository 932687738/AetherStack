# SuperAgents 平台 Agent 注册表界面

## Nebula Desk / Agent Hub 需求说明（前提/操作/结果）
> 运维与开发者在 Nebula Desk 中查看 SuperAgents 平台持久化 Agent 注册表，完成注册与健康探测，与既有「本地 Bean 快照」只读页并存。
> 后端契约已存在于 SuperAgents REST；本能力仅补全前端界面与 API 客户端。详见 proposal `aether-agent/superagents-registry-ui`。

---

## Requirements

### 功能组 1：注册表浏览

<a name="req-1"></a>
### Requirement: 1. 查看平台 Agent 注册表列表

<a name="openspec-req-1"></a>系统应当（SHALL）在 Agent Hub 分区提供独立入口，展示当前租户下 SuperAgents 平台已注册 Agent 列表；每条记录至少包含标识、展示名、状态与版本。

#### 场景: 进入注册表页面
- **前提**：用户已登录 Nebula Desk，后端 SuperAgents 服务可用。
- **操作**：从 Agent Hub 导航进入「平台 Agent 注册表」页面。
- **结果**：页面加载并展示注册表列表；加载中显示占位态；失败时展示可重试的错误提示。

#### 场景: 注册表为空
- **前提**：当前租户尚无已注册 Agent。
- **操作**：打开注册表页面。
- **结果**：展示空状态说明与引导注册的操作入口，而非空白页。

---

<a name="req-2"></a>
### Requirement: 2. 与本地 Agent 快照页隔离

<a name="openspec-req-2"></a>系统应当（SHALL）保留既有 `/agent-hub/agents` 本地 Bean 快照只读页的行为与布局不变；平台注册表须通过**新增路由**提供，不得替换或破坏原页面默认展示。

#### 场景: 访问原有 Agent 列表页
- **前提**：用户习惯使用本地 Agent 快照页。
- **操作**：打开 `/agent-hub/agents`。
- **结果**：仍展示 agent-hub 状态接口返回的本地子 Agent 列表；页面标题与交互与变更前一致。

---

### 功能组 2：注册与健康探测

<a name="req-3"></a>
### Requirement: 3. 注册新平台 Agent

<a name="openspec-req-3"></a>系统应当（SHALL）允许具备管理权限的用户通过表单提交 Agent 元数据（标识、展示名、能力描述、Spring Bean 名、可选健康检查地址、权限标签），完成平台注册。

#### 场景: 成功注册
- **前提**：用户已配置有效管理密钥（若后端启用）；表单字段合法且标识在租户内唯一。
- **操作**：填写注册表单并提交。
- **结果**：提示注册成功；列表刷新并出现新 Agent；表单关闭或重置。

#### 场景: 重复标识
- **前提**：租户内已存在同名 Agent。
- **操作**：以相同标识再次提交注册。
- **结果**：展示后端返回的冲突错误信息；不静默覆盖；列表不变。

#### 场景: 管理密钥无效
- **前提**：后端启用了管理 API 密钥校验。
- **操作**：未配置或配置错误密钥后提交写操作。
- **结果**：展示未授权或密钥无效提示；引导用户在页面内配置管理密钥后重试。

---

<a name="req-4"></a>
### Requirement: 4. 按需健康探测

<a name="openspec-req-4"></a>系统应当（SHALL）允许用户对注册表中指定 Agent 触发一次健康探测，并在界面上展示探测后的最新状态。

#### 场景: 探测成功
- **前提**：列表中存在带健康检查地址的 Agent。
- **操作**：点击该行的「健康探测」操作。
- **结果**：显示探测进行中状态；完成后更新该行状态展示；成功时给出轻量反馈。

#### 场景: 探测失败
- **前提**：Agent 健康端点不可用。
- **操作**：触发健康探测。
- **结果**：行状态更新为不可用或等价展示；展示可读失败说明，不导致整页崩溃。

---

### 功能组 3：租户与密钥配置

<a name="req-5"></a>
### Requirement: 5. 租户与管理密钥配置

<a name="openspec-req-5"></a>系统应当（SHALL）在与 Skill 管理台一致的模式下，支持用户配置租户标识与管理 API 密钥（本地存储），供注册表读写在请求头中携带。

#### 场景: 配置租户后刷新列表
- **前提**：用户需要查看非默认租户注册表。
- **操作**：在页面设置区修改租户标识并保存，然后刷新列表。
- **结果**：列表按新租户重新加载；设置持久化至本地，刷新浏览器后仍生效。

---

### 功能组 4：非破坏性与体验

<a name="req-6"></a>
### Requirement: 6. 不影响既有功能与导航布局

<a name="openspec-req-6"></a>系统应当（SHALL）以增量方式挂载新菜单项与路由；不得修改智能体对话、知识库、Skill 管理台及 BasicLayout 整体结构；新页面视觉风格与 Agent Hub 现有卡片/List 模式保持一致（Impeccable 验收）。

#### 场景: 变更后回归既有页面
- **前提**：本能力已上线。
- **操作**：依次访问对话页、Skill 管理台、原 agents 快照页。
- **结果**：上述页面功能、路由与布局与变更前一致，无回归缺陷。

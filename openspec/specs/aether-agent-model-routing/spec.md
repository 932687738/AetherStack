# 多模型路由

## Agent Hub / ModelProvider 与模型路由 需求说明（前提/操作/结果）
> 解耦 LLM 厂商，按任务复杂度、成本、延迟动态选模型；配置可切换、支持版本与灰度。
> 交付阶段：**P1**。详见 proposal `aether-agent/model-routing`。

---

## Requirements

<a name="req-1"></a>
### Requirement: 1. 模型提供商抽象 [P1]

<a name="openspec-req-1"></a>系统应当（SHALL）通过统一模型提供商接口接入不同 LLM 后端（如 DashScope、OpenAI 兼容、本地模型）；业务代码不得硬编码单一厂商 API。

#### 场景: 切换默认聊天模型
- **前提**：配置中心修改默认 chat 模型标识。
- **操作**：重启或热刷新配置后发起对话。
- **结果**：请求走新模型；无需改 Java 业务类。

---

<a name="req-2"></a>
### Requirement: 2. 按任务类型选模型 [P1]

<a name="openspec-req-2"></a>系统应当（SHALL）使模型路由器根据任务类型（如意图识别、复杂推理、嵌入）选择不同模型档位：轻量任务用小模型，复杂推理用大模型。

#### 场景: 总路由意图识别
- **前提**：路由策略配置「意图识别 → 小模型」。
- **操作**：用户发起对话，总路由执行意图分类。
- **结果**：意图识别调用小模型；后续子 Agent 复杂推理可升级大模型。

---

<a name="req-3"></a>
### Requirement: 3. 模型配置灰度 [P2]

<a name="openspec-req-3"></a>系统应当（SHALL）支持按租户或流量百分比将部分请求路由至新版本模型，用于灰度验证。

#### 场景: 10% 流量试用新模型
- **前提**：灰度规则设为 10% 租户使用 model-v2。
- **操作**：同一时段内多租户并发对话。
- **结果**：约 10% 请求使用 v2，其余 v1；Trace 可区分模型版本。

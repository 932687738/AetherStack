# AI 流程管理（Flow Management）

## 流程生命周期管理 需求说明（前提/操作/结果）

> 描述 AI 流程的 CRUD、版本管理、启用/禁用、发布等管理操作的业务场景与边界。

---

## ADDED Requirements
（新增用户故事）

<a name="req-1"></a>
### Requirement: 1. 流程 CRUD

<a name="openspec-req-1"></a>系统应当（SHALL）提供流程的创建、查询、更新、删除操作，支持列表分页与条件筛选。

#### 场景: 创建新流程
- **前提**：用户有流程管理权限
- **操作**：用户填写流程名称、描述，点击创建
- **结果**：系统创建流程记录（状态为草稿），自动跳转到流程设计器

#### 场景: 流程列表查询
- **前提**：系统中存在多个流程
- **操作**：用户访问流程管理页面，可按名称、状态、创建时间筛选
- **结果**：分页展示流程列表，包含名称、描述、状态、版本、创建时间、更新时间

#### 场景: 删除流程
- **前提**：流程状态为草稿或已禁用
- **操作**：用户点击删除并确认
- **结果**：流程及其所有版本被软删除；若流程被应用引用，提示先解除关联

---

<a name="req-2"></a>
### Requirement: 2. 流程版本管理

<a name="openspec-req-2"></a>系统应当（SHALL）支持流程版本管理，每次发布生成新版本，支持版本回滚。

#### 场景: 发布流程版本
- **前提**：流程处于草稿状态或已有已发布版本
- **操作**：用户点击"发布"按钮
- **结果**：当前流程定义快照为新版本（版本号自增），状态变为已发布；旧版本保留可追溯

#### 场景: 版本回滚
- **前提**：流程存在多个已发布版本
- **操作**：用户选择历史版本并点击"回滚到此版本"
- **结果**：流程定义恢复为选定版本的内容，生成新版本记录

#### 场景: 查看版本历史
- **前提**：流程存在多个版本
- **操作**：用户点击"版本历史"
- **结果**：展示版本列表：版本号、发布时间、发布人、流程定义摘要

---

<a name="req-3"></a>
### Requirement: 3. 流程启用与禁用

<a name="openspec-req-3"></a>系统应当（SHALL）支持流程的启用/禁用状态切换，禁用后关联应用不可调用该流程。

#### 场景: 禁用已发布流程
- **前提**：流程处于已发布且启用状态
- **操作**：用户点击"禁用"
- **结果**：流程状态变为禁用；关联应用调用该流程时返回友好错误提示

#### 场景: 启用已禁用流程
- **前提**：流程处于禁用状态
- **操作**：用户点击"启用"
- **结果**：流程状态变为启用；关联应用可正常调用

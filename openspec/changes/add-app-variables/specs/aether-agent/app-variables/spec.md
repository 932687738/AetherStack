# AI 应用变量

## 应用变量 需求说明（前提/操作/结果）

> Agent 应用可声明运行时变量，用户在对话前填写后注入 Prompt，实现个性化回复。  
> 能力边界：租户内 Agent 注册配置；不涉及 Prompt 市场模板版本管理变更。

---

## ADDED Requirements

### 功能组 1：变量定义与校验

<a name="req-1"></a>
### Requirement: 1. 管理员为 Agent 应用定义变量

<a name="openspec-req-1"></a>系统应当（SHALL）允许租户管理员在 Agent 应用配置中维护变量清单，每条变量含名称、类型、默认值、描述及是否必填。

#### 场景: 新增字符串变量
- **前提**：管理员已登录且具备 Agent 配置权限
- **操作**：在应用配置中新增变量 `user_name`，类型为文本，默认值「访客」，标记为必填
- **结果**：保存成功后，该 Agent 的变量清单包含 `user_name` 且可在对话流程中被引用

#### 场景: 变量名校验失败
- **前提**：管理员编辑 Agent 变量
- **操作**：输入变量名 `user-name`（含连字符）
- **结果**：系统拒绝保存并提示变量名仅允许字母、数字、下划线

---

<a name="req-2"></a>
### Requirement: 2. Prompt 模板引用应用变量

<a name="openspec-req-2"></a>系统应当（SHALL）支持在 Agent 的 System Prompt 中使用 `{{变量名}}` 占位符，并在对话发起前用用户提供的变量值完成替换。

#### 场景: 变量成功注入 Prompt
- **前提**：Agent 的 System Prompt 含 `你好，{{user_name}}`；用户已填写 `user_name=张三`
- **操作**：用户发送首条对话消息
- **结果**：实际送入模型的 System Prompt 中 `{{user_name}}` 被替换为经安全转义后的「张三」

#### 场景: 未填必填变量
- **前提**：Agent 存在必填变量 `user_name` 且用户尚未填写
- **操作**：用户尝试发送对话
- **结果**：系统阻断发送并引导用户先完成变量填写

---

### 功能组 2：对话前填写与持久化

<a name="req-3"></a>
### Requirement: 3. 对话前弹出变量填写表单

<a name="openspec-req-3"></a>系统应当（SHALL）在用户进入某 Agent 对话且存在未填写的必填变量（或无会话级缓存值）时，展示变量填写表单；填写完成后方可继续对话。

#### 场景: 首次进入对话填写变量
- **前提**：Agent 配置了必填变量 `company`；用户首次打开该 Agent 对话页
- **操作**：在表单中填写 `company=星云科技` 并确认
- **结果**：表单关闭，变量值绑定到当前会话；后续同会话消息不再重复弹出（除非变量定义变更）

#### 场景: 使用默认值跳过表单
- **前提**：Agent 变量均为非必填且均有默认值
- **操作**：用户进入对话并直接发送消息
- **结果**：系统使用默认值完成 Prompt 替换，不阻断对话

---

<a name="req-4"></a>
### Requirement: 4. 变量值安全与大小限制

<a name="openspec-req-4"></a>系统应当（SHALL）对每个变量值施加长度上限（单变量不超过 1KB），并对用户输入做 Prompt 注入防护后再参与模板替换。

#### 场景: 超长变量值被拒绝
- **前提**：用户在变量表单输入超过 1KB 的文本
- **操作**：提交表单
- **结果**：系统提示超长并拒绝提交

#### 场景: 可疑注入内容被过滤
- **前提**：用户填写含 `ignore previous instructions` 类注入片段的变量值
- **操作**：确认并发起对话
- **结果**：注入标记被过滤或转义，不破坏 System Prompt 结构

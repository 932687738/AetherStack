# AI 模型管理（Model Management）

## 模型配置与生命周期管理 需求说明（前提/操作/结果）

> 描述 AI 模型配置的 CRUD、测试激活、自动降级等业务场景与边界。

---

## ADDED Requirements
（新增用户故事）

<a name="req-1"></a>
### Requirement: 1. 模型配置 CRUD

<a name="openspec-req-1"></a>系统应当（SHALL）提供 AI 模型配置的创建、查询、更新、删除操作，支持多提供商和多模型管理。

#### 场景: 创建模型配置
- **前提**：用户有模型管理权限
- **操作**：填写模型名称、选择提供商（DeepSeek/OpenAI/通义千问/Ollama/自定义）、填入 API Key、Base URL、模型名、参数（temperature、max_tokens 等）
- **结果**：模型配置保存成功，初始状态为"未激活"

#### 场景: 模型列表查询
- **前提**：系统中存在多个模型配置
- **操作**：按名称、提供商、状态筛选
- **结果**：分页展示模型列表：名称、提供商、模型名、状态（未激活/已激活/已禁用）、是否默认、创建时间

#### 场景: 更新模型配置
- **前提**：模型配置存在
- **操作**：修改 API Key、参数等
- **结果**：配置更新成功；若模型已激活，缓存自动刷新

#### 场景: 删除模型配置
- **前提**：模型未被设为默认模型
- **操作**：点击删除并确认
- **结果**：模型配置软删除；若为默认模型则拒绝删除并提示

<a name="req-2"></a>
### Requirement: 2. 模型测试与激活

<a name="openspec-req-2"></a>系统应当（SHALL）支持在线测试模型连通性，测试通过后方可激活。

#### 场景: 测试模型连通性
- **前提**：模型配置已保存
- **操作**：点击"测试"按钮，系统向该模型发送一条简单测试消息
- **结果**：返回测试结果（成功/失败+错误原因、响应时间、Token 消耗）

#### 场景: 激活模型
- **前提**：模型测试通过
- **操作**：点击"激活"按钮
- **结果**：模型状态变为"已激活"，可被对话路由选用

#### 场景: 测试失败时拒绝激活
- **前提**：模型测试失败（API Key 错误、网络不通等）
- **操作**：尝试激活模型
- **结果**：系统拒绝激活，提示"请先通过连通性测试"

---

<a name="req-3"></a>
### Requirement: 3. 默认模型与自动降级

<a name="openspec-req-3"></a>系统应当（SHALL）支持设置默认模型，并在模型不可用时自动降级。

#### 场景: 设置默认模型
- **前提**：存在已激活的模型
- **操作**：在模型列表中将某模型设为默认
- **结果**：该模型标记为默认；原默认模型自动取消默认标记（全局唯一默认）

#### 场景: 按任务类型路由模型
- **前提**：系统配置了多个已激活模型，不同模型绑定不同任务类型（意图路由/推理/嵌入）
- **操作**：对话请求到达，需要选择模型
- **结果**：按任务类型匹配已激活模型；若该类型无可用模型，降级到默认模型

#### 场景: 模型不可用时自动降级
- **前提**：当前路由选中的模型调用失败（超时/API 错误）
- **操作**：系统自动重试
- **结果**：降级到同任务类型的其他已激活模型；若无其他可用模型，降级到默认模型；默认模型也不可用时返回明确错误

---

<a name="req-4"></a>
### Requirement: 4. 提供商适配

<a name="openspec-req-4"></a>系统应当（SHALL）支持多种模型提供商的统一接入，新增提供商仅需配置无需改代码。

#### 场景: 内置提供商支持
- **前提**：用户创建模型配置
- **操作**：选择提供商下拉列表
- **结果**：展示 DeepSeek、OpenAI、通义千问（DashScope）、Ollama（本地）、自定义 OpenAI 兼容 五种内置选项

#### 场景: 自定义 OpenAI 兼容提供商
- **前提**：用户使用私有部署的 OpenAI 兼容模型
- **操作**：选择"自定义"，填入 Base URL + API Key + 模型名
- **结果**：系统通过 OpenAI 兼容协议接入，无需额外代码

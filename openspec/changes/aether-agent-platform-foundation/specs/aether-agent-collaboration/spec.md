# 多 Agent 协作

## Agent Hub / 多 Agent 协作与上下文 需求说明（前提/操作/结果）
> 总路由分发；同类连续请求保持子 Agent 会话粘性；全局记忆与上下文防膨胀；单请求多 Agent 并发/串行；跨会话恢复未完成流程。
> 交付阶段：**P2**（粘性路由 P1 可简化）。详见 proposal `aether-agent/collaboration`。

---

## ADDED Requirements
（新增用户故事）

<a name="req-1"></a>
### Requirement: 1. 会话粘性路由 [P1]

<a name="openspec-req-1"></a>系统应当（SHALL）对同一 session 内**同类连续**用户请求，优先保持在当前子 Agent 会话，避免重复总路由切换；意图类别变化时重新路由。

#### 场景: 连续客服追问
- **前提**：用户上一问已路由至客服 Agent。
- **操作**：用户追问订单细节（仍属客服域）。
- **结果**：继续由客服 Agent 处理；SSE 前缀不重复全量路由说明。

#### 场景: 意图类别切换
- **前提**：用户从客服话题转向数据分析。
- **操作**：发送新消息。
- **结果**：总路由重新识别并切换至数据分析 Agent。

---

<a name="req-2"></a>
### Requirement: 2. 上下文防膨胀 [P2]

<a name="openspec-req-2"></a>系统应当（SHALL）对长对话实施摘要压缩、关键信息持久化与滑动窗口策略，防止 Prompt 超出模型上下文上限。

#### 场景: 超长对话
- **前提**：单 session 消息数超过配置阈值。
- **操作**：用户继续提问。
- **结果**：早期历史被摘要替代；关键实体仍可从长效记忆检索。

---

<a name="req-3"></a>
### Requirement: 3. 跨会话恢复挂起流程 [P3]

<a name="openspec-req-3"></a>系统应当（SHALL）支持将未完成的多步流程（含 CompileGraph 检查点）持久化；用户稍后携带同一 sessionId 返回时可恢复执行。

#### 场景: 审批挂起后恢复
- **前提**：流程在人工审批节点挂起，状态已写库。
- **操作**：用户 24 小时后同 session 发送「继续」。
- **结果**：从挂起点恢复；不重复已完成步骤。

---

<a name="req-4"></a>
### Requirement: 4. 高频跨 Agent 流程封装 [P2]

<a name="openspec-req-4"></a>系统应当（SHALL）支持将高频固定跨 Agent 协作封装为单一 CompileGraph Skill，减少总路由重复拆解开销。

#### 场景: 固定「查单+分析」流程
- **前提**：产品定义标准 Skill「订单洞察」含客服查单与分析 Agent 串行。
- **操作**：用户触发该 Skill。
- **结果**：一次 Skill 调用完成串行协作；总路由不每次重新拆解。

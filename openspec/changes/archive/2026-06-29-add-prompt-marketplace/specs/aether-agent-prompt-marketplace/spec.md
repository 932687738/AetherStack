# Prompt 市场 / 快捷指令

## 需求说明（前提/操作/结果）

- **背景**：JeecgBoot 等同类平台提供了 Prompt 预置市场与快捷指令能力，用户可快速选用模板降低 AI 应用配置门槛。AetherStack 目前缺少此能力，用户需手动编写完整 Prompt。
- **目标**：提供 Prompt 预置市场（按场景分类的模板库）、应用级快捷指令（一键触发预置命令）、以及 AI 辅助 Prompt 生成，降低 AI 应用使用与配置门槛。

---

## ADDED Requirements

<a name="req-1"></a>
### Requirement: 1. Prompt 市场浏览与选用

<a name="openspec-req-1"></a>系统应当（SHALL）提供 Prompt 预置市场，以分类模板库形式展示预置 Prompt，用户可浏览、搜索并选用模板填入目标应用。

#### 场景: 按分类浏览市场模板
- **前提**：系统中已预置 Prompt 模板数据（含分类标签：翻译、摘要、代码审查、写作等）
- **操作**：用户打开 Prompt 市场，选择某一分类
- **结果**：展示该分类下的所有 Prompt 模板列表，显示名称、简介和适用场景

#### 场景: 搜索市场模板
- **前提**：市场中存在多个模板
- **操作**：用户输入关键词搜索
- **结果**：返回名称或描述匹配关键词的模板列表

#### 场景: 选用模板到应用
- **前提**：用户已浏览并选中某一模板
- **操作**：点击「使用此模板」，选择目标 AI 应用
- **结果**：模板内容写入目标应用的 Prompt 配置（System Prompt 字段），用户可在此基础上修改

#### 场景: 收藏与取消收藏
- **前提**：用户在市场中看到感兴趣的模板
- **操作**：点击收藏/取消收藏按钮
- **结果**：模板加入/移出用户收藏列表，可在「我的收藏」筛选项中查看

---

<a name="req-2"></a>
### Requirement: 2. 快捷指令管理

<a name="openspec-req-2"></a>系统应当（SHALL）支持为每个 AI 应用配置快捷指令（预置命令），以应用为单位进行增删改查，指令可绑定快捷键或展示为操作面板按钮。

#### 场景: 创建快捷指令
- **前提**：用户有目标应用的编辑权限
- **操作**：填写指令名称、Prompt 内容、图标（可选）
- **结果**：指令保存成功，绑定到该应用

#### 场景: 查询应用快捷指令列表
- **前提**：应用已配置若干快捷指令
- **操作**：进入应用快捷指令管理页
- **结果**：展示该应用的所有快捷指令，按创建时间排序

#### 场景: 编辑与删除快捷指令
- **前提**：应用存在快捷指令
- **操作**：修改指令内容或删除指令
- **结果**：修改立即生效；删除后指令从面板消失

---

<a name="req-3"></a>
### Requirement: 3. 快捷指令一键触发

<a name="openspec-req-3"></a>系统应当（SHALL）在对话界面提供快捷指令面板，用户点击指令后以预置 Prompt 发起对话，无需手动输入。

#### 场景: 从对话面板触发快捷指令
- **前提**：当前应用已配置快捷指令；用户处于对话界面
- **操作**：点击快捷指令面板中的某一指令按钮
- **结果**：以该指令的 Prompt 内容作为用户消息发送到对话流，触发 AI 响应

#### 场景: 指令执行结果展示
- **前提**：快捷指令已触发
- **操作**：等待 AI 响应
- **结果**：响应按标准 SSE 流式输出到对话窗口，与普通对话体验一致

---

<a name="req-4"></a>
### Requirement: 4. AI 辅助生成 Prompt

<a name="openspec-req-4"></a>系统应当（SHALL）支持用户输入简短描述后由 AI 自动生成 Prompt 模板，生成结果可预览、编辑并保存。

#### 场景: 描述需求生成 Prompt
- **前提**：用户进入 Prompt 生成界面
- **操作**：输入简短需求描述（如「帮我写一个代码审查助手」），点击生成
- **结果**：AI 返回结构化 Prompt 模板，展示在预览区域

#### 场景: 编辑并保存生成结果
- **前提**：AI 已生成 Prompt 模板
- **操作**：用户在预览区修改内容，点击保存
- **结果**：修改后的 Prompt 保存为用户自定义模板，可在模板管理或应用中选用

#### 场景: 生成失败处理
- **前提**：AI 生成请求已发出
- **操作**：LLM 调用超时或返回错误
- **结果**：界面友好提示「生成失败，请稍后重试」，不中断用户操作

## 2. 重构目标

- 将单模块项目拆分为 **Maven 多模块项目**，使用父子 POM 管理
- **优先按业务域边界划分**，再按技术横切面补充基础设施模块，实现高内聚低耦合
- 抽象可扩展接口层（多向量库、多机器人、多 AI 框架、多模型）
- 保持所有现有功能完全不变，只调整结构、包名、import 和依赖关系
- 包名前缀**保留** `com.yxy.deepseek`，不做全局重命名（降低 import 修改量）

## 3. 模块划分方案（最终版）

> **核心修正**：原方案以 `web-api` 单模块承载所有业务是错误的。项目已有三个成熟的业务域，必须各自独立成模块。

### 3.0 总览

```
ai-platform/（根 POM）
│
├── [横切基础层]
├── common/
├── ai-core/
├── ai-spring/
├── ai-alibaba/
├── ai-langchain/
├── vector-store-api/
├── vector-store-pgvector/
├── platform-persistence/
├── nosql/
├── mcp-integration/
├── bot-api/
├── bot-feishu/
├── human-loop/
│
├── [业务域层]
├── knowledge-hub/
├── agent-hub/
├── aether-platform/
│
├── [非生产]
├── learning/
│
└── application/
```

- 管理 Spring Boot 3.4.3、Spring AI 1.1.2、Alibaba AI 1.1.2.2、LangChain4j 0.36.2 等所有第三方版本
- 定义所有子模块，Spring Boot Maven Plugin 只在 `application` 模块启用

### 3.2 公共基础模块（`common`）

**来源**：`com.yxy.deepseek.common`、`com.yxy.deepseek.config`（全局 Jackson/线程池配置）、`com.yxy.deepseek.helper`

**内容**：

- Jackson ObjectMapper 配置、全局线程池 Bean

**约束**：不允许依赖任何业务模块，可被所有模块依赖。

### 3.3 AI 核心抽象模块（`ai-core`）

> **重要修正**：`ai-core` 是**框架无关的 AI 能力抽象层**，不含任何 Spring AI / LangChain 的具体代码。

**内容**：
```java
// 框架无关接口定义
ChatService            // 统一对话接口（流式 + 非流式）
EmbeddingService       // 统一向量化接口
LlmCompletionPort      // 底层模型调用端口（已在 superAgents domain 层，直接提升）
ToolCallingService     // 工具调用接口

// 通用值对象
AiContext              // AI 调用上下文（会话 ID、租户 ID、用户 ID）
AiProperties           // 统一配置属性类（与框架解耦）
PromptTemplate         // Prompt 模板管理
```

**来源**：
- `superAgents.domain.model.LlmCompletionPort`（提升至此模块）
- `superAgents.domain.model.ModelRouter` 的接口部分
- 从各 Service 中提取公共方法签名

**依赖**：只依赖 `common`。

### 3.4 Spring AI 实现模块（`ai-spring`）

**来源**：`springai.config`（PgVector 配置、ChatMemory 配置、RAG Audit 配置）、`springai.rag`

**内容**：
- Spring AI `ChatClient`、`EmbeddingModel` 的 Bean 配置
- 实现 `ai-core` 的 `ChatService`、`EmbeddingService` 接口
- OpenAI 兼容接口配置（DashScope / qwen-turbo）
- `application-ai-spring.yml`（Spring AI 专用配置）

**依赖**：`ai-core`、`common`、`vector-store-api`（通过接口调向量库，不直接依赖 pgvector）

### 3.5 Alibaba AI / CompiledGraph 模块（`ai-alibaba`）

> **原方案遗漏**。`CompiledGraph` 是项目编排知识库流水线和平台 Skill 执行的核心机制，必须独立封装。

**内容**：

- `AbstractKnowledgeGraphNode` 等图节点基类
- Graph Builder 工厂、状态键常量基类
- 实现 `ai-core` 中与 Agent 编排相关的接口

**来源**：`knowledgehub.graph.AbstractKnowledgeGraphNode`、`knowledgehub.graph.ConfigurableGraphBuilder`（基类部分）

**依赖**：`ai-core`、`common`

### 3.9 平台持久化基础模块（`platform-persistence`）

> **重要修正**：原方案的 `rdbms` 模块将所有 Repository 集中一处，会打碎业务内聚。本模块**只提供共享基础设施**，各业务域的 Repository 实现留在自己模块。

**内容**：
- `DataSource` 配置（PostgreSQL 连接池）
- MyBatis 扫描基类配置、公共 TypeHandler
- Flyway 主配置（`spring.flyway.locations` 聚合扫描多个域的迁移脚本）
- `BaseRepository<T, ID>` 接口（可选的通用 CRUD 基类）

**Flyway 脚本归属规则**：
```
knowledge-hub/src/main/resources/db/migration/   ← 知识库相关表（V3~V7 等）
aether-platform/src/main/resources/db/migration/ ← 平台治理表（V8~V16 等）
platform-persistence/src/main/resources/db/migration/ ← 共享基础表（V1~V2）
```
`platform-persistence` 通过 `spring.flyway.locations=classpath:db/migration,classpath:db/migration/knowledge,...` 聚合。

**依赖**：`common`

## 5. 前置收敛（模块化开始前必须完成）

**这四件事不做，模块化无法安全进行。**

### 5.1 消灭 `agents.knowledgehub` staged 副本【最高优先级】

```bash
# 当前 staged 但磁盘未落盘的 agents/knowledgehub 是 knowledgehub 的全量副本
# 必须明确放弃此迁移路径，回滚 staged 变更
git restore --staged src/main/java/com/yxy/deepseek/agents/knowledgehub/
# 同时回滚 agents/knowledge 下 staged 的全量版
git restore --staged src/main/java/com/yxy/deepseek/agents/knowledge/
```

## 7. 通用约束与规范

### 包名规范

- **包名前缀保留 `com.yxy.deepseek`**，不做全局重命名
- 子模块包结构：`com.yxy.deepseek.<业务域>.<层>`
  - 例：`com.yxy.deepseek.knowledgehub.domain.KnowledgeBase`

### 配置文件拆分规则

- 各子模块专用配置命名为 `application-<模块名>.yml`，放在各自 `src/main/resources/` 下
- `application` 模块主配置通过 `spring.config.import` 显式导入

### 可见性规则

- 移动后若因跨模块引用导致编译错误，允许将 package-private 类/方法改为 `public`
- 改动处必须加注释：`/* 重构提升可见性，原为 package-private */`

### Bean 扫描

- 所有 `@Component`、`@Service`、`@Repository` 注解**保留原样**
- `application` 主类用 `scanBasePackages = "com.yxy.deepseek"` 确保全量扫描
- 若某模块有自定义 Spring Boot AutoConfiguration，配置 `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`

### Git 历史保留

- 移动文件时使用 `git mv` 或 IDE 重构移动功能
- 每次阶段完成后，以清单形式记录"旧路径 → 新路径"，便于追溯
